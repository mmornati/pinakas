Why

Fast agents, drifting boards.

Running coding agents from a Kanban board works: stories ship three to six times faster than estimated. But left alone, agents drift, and the board stops telling the truth.

✕

Cards never move

The PR merged on Tuesday. The card is still in In Progress, and the coordinator plans around it.

✕

PRs nobody claimed

An agent opens a pull request for a story it picked on its own, or for no story at all.

✕

No record of the cost

The session ends without actuals: no duration, no tokens, no review findings. Nothing to learn from.

A skill can describe the workflow. It can’t enforce it. pinakas does.

How it works

Four layers, one binary.

All the logic lives in the CLI. Each agent tool gets a one-line hook that calls it, so there is one implementation to maintain and a few small wiring files.

i

pinakas CLI

Gives agents write access to the board: claim, move, actuals, status, release. The claim lives in the git directory, so every worktree and every parallel agent tracks its own card.

v0.1
ii

Agent hooks

Session start injects the live board. A pre-tool hook blocks gh pr create for an unclaimed card. A stop hook blocks finishing without actuals.

Claude Code · Copilot · Codex
iii

GitHub Action

Moves the card when a PR opens, goes back to draft or merges, and posts durations measured from timestamps.

v0.2
iv

Required check

The PR closes a card of the board, every linked card has actuals, and risky labels carry an approval from a human.

The life of a card

From Ready to Done, nothing skipped.

Humans write and order the cards. Agents do the work in between. pinakas keeps both honest at every transition.

  1. Ready

    Pick from the board

    At session start the hook injects the live board. The coordinator skill hands one ready card to one implementer, in its own worktree.

    pinakas status --hook
  2. In Progress

    Claim and start the clock

    The agent claims the card: it is assigned, moved, and the claim time recorded. No PR can be opened before this.

    pinakas claim 42
  3. In Review

    Open the pull request

    The Action moves the card to review. The required check runs: closes a card, actuals recorded, human approval on risky labels.

    pinakas / check
  4. Done

    A human merges

    The card moves to Done and a timing comment lands on the issue: claim to PR, PR to merge, claim to merge.

    pinakas sync-pr

Guardrails

Hooks that say no, and say why.

A blocked agent gets the exact command that unblocks it, so it corrects itself instead of giving up. Claude Code gets exit code 2 and the reason; Copilot and Codex get a deny or block decision as JSON.

PreToolUse · Bash
$ gh pr create --fill
✕ blocked by pinakas check-pr
pinakas: no card is claimed in this working
tree. Run `pinakas status` to pick an unblocked
card, then `pinakas claim <issue>` before
opening a pull request.

No PR without a claim. The card must be claimed here, assigned, and in the in-progress column.

Stop
● agent is about to finish
✕ blocked by pinakas check-stop
pinakas: card #42 (Add OAuth login) has no
actuals yet. Record them with `pinakas actuals
42 --tokens <n> --first-pass=<yes|no>` before
stopping, or `pinakas release` if abandoned.

No stop without actuals. Or an explicit release, so abandoned work is visible too.

Guardrails fail open. A broken guardrail must never stop all work. If the hook input is malformed or the board can’t be reached, pinakas prints a warning and checks only what it can verify locally. Outside a repository with .pinakas.yml, the hooks do nothing.

Measuring

Every story, the same numbers.

So that experiments can be compared: a new model, a new prompt, a new skill. At merge, the Action adds durations measured from timestamps only, and pinakas report turns it all into answers.

Duration
47 min

From claim to actuals, from timestamps.

Tokens
182k

Reported by the agent with --tokens.

First pass
yes

Did review pass without changes?

Findings
0 · 2

Review findings by severity: major, minor.

# recorded as an issue comment with a machine-readable marker the CI check parses back
pinakas actuals 42 --tokens 182000 --first-pass yes --findings major=0,minor=2
pinakas report

From actuals to answers. Per story and in aggregate, as a table, JSON, CSV or Markdown. The done column by default; --all or --status to widen it.

Fast but fragile? It shows.

When a bug traces back to a delivered story, link them. The report counts defects found within 30 days of delivery, and the defect rate only uses stories whose window has ended.

pinakas defect 41 57   # bug #57 came from story #41

The Action posts it weekly to the job summary:

- uses: mmornati/pinakas@v0.3.1
  with:
    command: report
    args: --since 7d
    token: ${{ secrets.PINAKAS_TOKEN }}

Quick start

On the board in five minutes.

You need Go 1.27+, the GitHub CLI signed in with the project scope, and a GitHub Project (v2) with a single-select Status field.

  1. Install the CLI

    One static binary. The project scope lets it read and move cards.

    go install github.com/mmornati/pinakas/cmd/pinakas@latest
gh auth refresh -s project

  2. Point it at your board

    Writes .pinakas.yml. Add --copilot or --codex for those agents, and --workflow for the Action and required check.

    pinakas init --owner <user-or-org> --project <number> --repo <owner/name>
pinakas status

  3. Install the Claude Code plugin

    Two skills (coordinator, implementer) and three hooks. Then ask your agent to pick the next ready story.

    /plugin marketplace add mmornati/pinakas
/plugin install pinakas@pinakas

Using GitHub Copilot or Codex, or want the board to follow your pull requests? Copilot setup · Codex setup · Action and required check
